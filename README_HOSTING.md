# Заявки на почту и перенос на хостинг

Получатель заявок: **mebelbutik.48@yandex.ru**.

Комплект содержит готовую форму и PHP-обработчик. Для рабочего сайта рекомендуем поддерживаемую ветку PHP 8.3+ и настроенную почтовую службу; совместимость кода начинается с PHP 8.1. На GitHub Pages PHP не выполняется; там сохранено открытие заполненного письма в почте посетителя. Яндекс Формы и отдельный платный сервис для этого варианта не нужны.

## Размещение

1. Загрузите содержимое архива в корень сайта, сохранив папки `api`, `js`, `css`, `fonts` и `images`. В папке сайта должны лежать `index.html` и `api/request.php`.
2. Включите поддерживаемую ветку PHP 8.3 или новее и HTTPS. Функция PHP `mail()` должна быть разрешена, а почтовая служба хостинга — настроена. Обработчик использует её, не подключается к Яндекс SMTP и не требует пароль от ящика получателя.
3. Отправитель по умолчанию — `no-reply@домен-сайта`. Если хостинг требует зарегистрированный почтовый ящик отправителя, создайте его на домене и задайте серверную переменную `MB48_MAIL_FROM` с этим адресом. Можно указать его непосредственно в параметре `mail_from` внутри `api/request.php`. Не указывайте адрес @yandex.ru как отправителя без настройки авторизованной отправки через Яндекс. При ограничениях попросите поддержку хостинга включить PHP mail и подтвердить настройки SPF/DKIM для отправителя.
4. Каталог временных файлов PHP должен быть доступен для записи. Обработчик создаёт там закрытую служебную папку с правами 0700; в ней нет имён, телефонов и текстов заявок. Конфигурация базы данных не нужна.
5. Отправьте тестовую заявку с нового домена и проверьте входящие и спам на mebelbutik.48@yandex.ru. Проверьте, что в письме есть имя, телефон, параметры проекта и отметка согласия. Успешный ответ PHP означает принятие письма почтовой службой хостинга, а не гарантированную доставку во входящие. До этой проверки реальную доставку нельзя считать подтверждённой.

Форма автоматически использует `api/request.php` на том же домене, без изменения адреса обработчика после переноса. Проверяйте сайт через HTTP/HTTPS, а не открытием HTML-файла с диска. Размещение на другом статическом хостинге без PHP не включает автоматическую отправку.

Если собственный домен сначала привязан к GitHub Pages, PHP всё ещё не работает. Временно задайте `requestEndpoint: ''` в `js/contact-settings.js`, чтобы оставить почтовый черновик. После переноса на PHP-хостинг верните `api/request.php` и проверьте доставку. Настройка только домена не является настройкой обработчика.

В сборке GitHub Pages папка `api` исключена, чтобы сервер не выдавал PHP текстом. В архиве для PHP-хостинга она сохранена. На PHP-хостинге GET к `api/request.php` должен возвращать JSON с HTTP 405, а не скачивание исходника.

## Поведение формы

- Имя, телефон РФ и отдельная галочка согласия проверяются в браузере и на сервере.
- Письмо содержит описание из квиза или 3D-конструктора.
- Пока запрос выполняется, повторное нажатие блокируется.
- Повтор запроса с тем же номером не отправляет письмо ещё раз; номер меняется при редактировании формы. Служебные записи учитываются в течение часа.
- Ограничение: 5 попыток в час с одного IP-адреса. Переданный посетителем email не может изменить получателя.
- При ошибке почты, недоступности PHP или неверном ответе сервера подтверждение отправки не показывается. Поля сохраняются в открытой странице, доступен черновик для ручной отправки. После обновления страницы данные не восстанавливаются.
- Контактные данные не записываются собственным кодом в cookies или браузерное хранилище.

Перед приёмом реальных обращений дополните реквизиты оператора и временные документы `privacy.html`, `consent.html`, `details.html` сведениями о выбранном хостинге, почтовой инфраструктуре и порядке обработки. Подготовка кода не подтверждает выполнение всех обязанностей оператора.

## Проверки разработчика

PHP: `php tests/test_request.php`.

Браузерные проверки: `node server.js`, затем `python -m unittest discover -s tests -v` с установленными зависимостями из `tests/requirements.txt` и Chromium. Почтовый транспорт в проверках подменяется локальным приёмником; реальных писем эти проверки не отправляют.
