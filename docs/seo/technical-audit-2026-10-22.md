## Границы GitHub Pages и отложенные действия

- Файл `robots.txt` управляет обходом только из корня хоста. Файл проекта `/mebelny-butik-48/robots.txt` не становится правилами для всего `stas5252.github.io`. Корневой robots на момент проверки не найден; ответ 404 сам по себе не запрещает обход. Без управления корнем хоста или переноса на собственный домен исправить это файлом в проекте нельзя. Доступ к root-репозиторию и его изменения не предполагались.
- GitHub Pages не даёт настроить произвольные HTTP 301 и серверные заголовки через `.htaccess`. Для дубля `/index.html` действует canonical. На будущем собственном хостинге нужно отдельно настроить единственный HTTPS-адрес, перенаправления и обработчик 404 с сохранением статуса; ссылка или JavaScript-переход не заменяют серверный 301.
- Права в Вебмастере и Search Console, отправка sitemap через кабинеты, региональность карточек, Метрика, Wordstat и реальные запросы/позиции отложены согласно просьбе «без аккаунтов». Тестовых кодов подтверждения нет. Наличие корректного sitemap и метатегов не доказывает индексацию или рост позиций.
- Семантическое ядро и редакционный план уже подготовлены в `semantic-core.json`, `service-pages.json` и `article-plan.md`. Частотность не измерена. Новые посадочные страницы и видимые SEO-тексты не публиковались согласно текущему ограничению.

Lighthouse запускается отдельно от браузерных тестов, чтобы они не конкурировали за CPU:

```bash
CHROME_PATH=/usr/bin/chromium npx --yes lighthouse 'https://stas5252.github.io/mebelny-butik-48/' --only-categories=performance,seo --chrome-flags='--headless --no-sandbox' --output=json --output-path=/tmp/butik-lighthouse.json
```
